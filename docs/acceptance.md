# Проверки и оставшиеся критерии приёмки

Это результаты выполненных проверок, а не обещание полной готовности. Полная приёмка ТЗ **не завершена** из-за `/clear`, штатного `/status` и оставшихся проверок сценариев с телефона.

Обновление после локальной настройки Telegram: оба сервиса работают; настоящие getMyCommands/getChatMenuButton подтвердили 13 команд с английскими описаниями и кнопку меню для разрешённого личного чата. Phone-to-PC и остальные Telegram end-to-end сценарии ниже всё ещё требуют отдельной проверки.

## Setup, меню и восстановление Gateway

Setup и описания Telegram-команд переведены на английский. Первая настройка проверена с mock Telegram: токен вводится через getpass, числовой ID и проекты — локально; конфиги создаются с 0600 в каталоге 0700, токен не печатается. Примеры содержат обязательные placeholders; исследовательские логи и окружение разработки находятся вне каталога публикуемых исходников.

Настройка обычной команды `codex` проверена в настоящих Fish, Bash и Zsh с тестовыми launchers: вызов без аргументов направляется в bridge, аргументы с shell-метасимволами сохраняются буквально. Проверены enable/disable, повторный запуск, сохранение настроек/backup, отказ при custom alias/function, symlink/hardlink и повреждённом managed block. Automatic launcher выбирает зарегистрированный проект по canonical cwd; вне списка запускается исходный CLI.

При недоступности бота обнаружен потерянный Gateway bind mount после пересоздания каталога IPC: host socket существовал, внутри namespace отсутствовал. Перезапуск только Gateway восстановил polling и обработку накопленных updates без перезапуска Controller. Missing socket теперь завершает Gateway, чтобы systemd пересоздал изоляцию; integration test проверяет закрытие API и отсутствие продвижения Telegram offset при недоставленном update. Это отдельный сбой от прежней неопределённой доставки Codex, причина которой остаётся неизвестной.


## Доставка итогового ответа и встроенных изображений

Добавлены integration/security проверки: финальный agentMessage при пустом turn/completed, исключение commentary/tool outputs, фильтрация секретов, сохранение хвоста длинного ответа при разбиении, отключение mirroring, старые thread/turn, повторный completion и повторный image item, strict base64/формат/размер, отсутствие чтения savedPath. Mock Gateway подтверждает PNG upload и финальный текст отдельными сообщениями без редактирования прежнего статуса; ack удаляет export. Setup проверяет согласие на пересылку, которое хранится только в приватном controller.toml. Автоматическая imageGeneration-доставка не объявляется блокирующим gate.

Формат проверен по JSON Schema установленного Codex 0.160.1; итоговые agentMessage обрабатываются через item/completed согласно [официальной документации App Server](https://learn.chatgpt.com/docs/app-server). Реальное событие imageGeneration содержит base64 result и savedPath; используется только result.

Живая проверка завершилась успешно: отдельный ephemeral thread на том же настоящем App Server ответил на безвредный запрос; Controller получил финальный ответ и создал отдельное уведомление. Файлы не изменялись, image generation повторно не запускалась. После установки оба пользовательских root Thread/Session ID сохранились. Пропущенные два итоговых ответа и готовое встроенное изображение доставлены из штатной истории через проверку result/outbox; Gateway подтвердил доставку.
